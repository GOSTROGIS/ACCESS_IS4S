What changes the finish?

Try a delay on a fictional small workshop project. Predict the finish, then check the schedule.

A teaching model, not the full Slipcurve app. This original sandbox uses finish-to-start links with no lag. Work can run in parallel. It does not solve crew limits, calendars, costs or real project risks.

Read the working-day boundaries

Start at 0. A two-day task runs from boundary 0 to boundary 2. Its successor can start at 2. There are no dates, weekends or inclusive day numbers here.

The fixed baseline finishes at 12. Its two paths are A → B → D → E → F = 12 days and A → C → E → F = 9 days.

How the calculation works
  • ES / EF: earliest start / finish. Work forwards. ES is the latest EF of the predecessors; EF = ES + duration.
  • LS / LF: latest start / finish without moving the project finish. Work backwards from the current finish. LF is the earliest LS of the successors; LS = LF − duration.
  • TF: total float = LS − ES. A task can use this time without moving the project finish, assuming other work stays as planned.
  • FF: free float = earliest successor ES − EF. It is time available without delaying a successor's earliest start. For a last task, use project finish − EF.
  • Float on a path is shared. Do not add task floats as if each task had a separate allowance.

What if one crew does both jobs?

B (frame) and C (order materials) can overlap in this model. If the same crew must do both, that overlap may not be possible. Decide which task goes first and build a revised plan. This sandbox does not automatically level resources. Critical-path results alone do not prove that a plan is workable.
