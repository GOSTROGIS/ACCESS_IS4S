# Owned GitHub repository synchronization

GitHub supplies committed default-branch changes to the intranet copies every two hours.

The scheduled synchronizer requires Windows and the configured Python command guard. It refuses to start Git without process-tree containment.

`github-sync.mjs --root <directory> --git <git.exe> --python <python.exe> --owner <account>` uses the existing Windows Git credential helper to authenticate to GitHub. It checks the authenticated account and pages all repositories owned by that account, including accessible private repositories. The temporary Git helper contains no credential value. The token stays in process memory during GitHub API calls and Git transfers.

The first run creates a shallow default-branch working copy with its Git history and origin metadata. Later runs fetch and fast-forward clean copies. Repositories with local edits, another checked-out branch, conflicting origin, linked paths, filter configuration or divergent commits get a status for review. Git hooks and global filters are disabled for these transfers. Empty repositories remain usable Git working copies and acquire their initial contents on a later run. The last result for each repository is recorded in `sync-status.json`.

Install `github-sync.mjs`, `github-sync-command.py`, and `project-command.py` under the chosen directory's `.sync-tools` folder. `Schedule GitHub Sync.ps1` registers a task every two hours using the owning Windows account at limited privilege. It needs explicit root, Node, Git, and Python executable paths. Updating an existing task preserves its original two-hour trigger anchor, owning account, and settings. A new task first runs two hours after registration. The task uses that account's existing credential helper while the user is signed in, allows one scheduled instance, and checks for updates after a missed start. Use `-RunNow` for an immediate check after the first mirror is ready.

Every Git command starts suspended and joins the existing non-breakaway Windows Job guard before executing. Its descendants close on deadline, normal launcher exit, or caller death. Commands have a ten-minute total deadline, two-MiB combined output limit, and HTTP low-speed refusal below 1,024 bytes per second for 45 seconds. Credential lookup has a 30-second deadline and 32-KiB output limit; its fixed protocol input stays in an in-memory pipe. GitHub API requests have 30-second deadlines and four-MiB response limits. Failures preserve the current mirror and report the repository as failed; later scheduled runs can retry.

An optional `--placements` JSON file can place selected repositories in named sibling directories of the mirror root. Its keys are repository names and its values are direct-child folder names. Absolute paths and directory traversal are refused. Keep this organizational configuration in the installed folder. The scheduler accepts the same file through `-Placements`. For a first clone, `--seed-root` can reuse an existing Git object store when it contains the authoritative remote commit. The new mirror repacks only that commit's reachable history into its own objects and removes its temporary alternate before publication. Local working files and unpublished descendant commits stay in their original checkout.
