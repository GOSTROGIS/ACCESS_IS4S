# Native owner sign-in

The installed Windows launcher can use the owner's existing Git Credential Manager sign-in. The Windows broker and authenticated guest CLI independently verify the real GitHub account against the protected owner login and numeric ID. The CLI issues a 256-bit, hashed, single-use handoff lasting 60 seconds. Its credential is sealed with the existing session TokenBox. The browser receives the normal Secure, HttpOnly, SameSite session cookie; it never receives the GitHub credential.

Each private secrets file needs a separate `session_key` and `native_signin` containing `product`, `owner_login` and `github_id`. The allowed products are `access` and `slipcurve`, using `http://127.0.0.2:8993` and `http://127.0.0.3:8994` respectively. Guest listeners bind only `127.0.0.1`; the approved SSH transport forwards the corresponding host loopback address. Databases, keys and cookie names are separate. Native mode rejects development authentication, proxy trust, other hosts and other origins. The OS installation must provision the verified owner's access entry; HTTP cannot create an owner or issue a handoff.

Use the installed product launcher to sign in. The internal `src/dash/server/native-issue.ts --product access|slipcurve` entry accepts its credential only through authenticated SSH stdin and returns its handoff only to the native broker. Never place credentials in arguments, URLs, source files or logs. Sign-out removes local sessions and pending handoffs without revoking the external credential manager's grant. Configured real OAuth credentials retain the normal OAuth flow.
